# 契约与实现漂移

## 检查来源

至少比对：

- 需求验收标准；
- 接口文档或 OpenAPI；
- Controller 路径和参数校验；
- Request/Response DTO；
- Service 状态和错误码；
- DAO/数据库字段；
- 已有接口测试和客户端调用。

## 漂移分类

| 类型 | 示例 |
|---|---|
| `PATH_DRIFT` | 文档路径和实际路由不同 |
| `FIELD_DRIFT` | 文档字段和响应字段不同 |
| `SEMANTIC_DRIFT` | 字段存在但含义或单位不同 |
| `STATE_DRIFT` | 文档状态和实际状态转换不同 |
| `ERROR_DRIFT` | 业务错误码或 HTTP 状态不同 |
| `DATA_DRIFT` | 接口显示值和数据库真实值不同 |

发现漂移时，Case 仍然可以生成，但必须同时记录期望契约、当前实现和验证限制。不能默默以代码行为替代需求，也不能默默以文档字段假设接口会返回。
