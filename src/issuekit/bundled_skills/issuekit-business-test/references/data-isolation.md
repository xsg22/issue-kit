# 测试数据隔离与可复现性

## 隔离优先级

1. 独立测试账号或租户；
2. 独立业务前缀和幂等键；
3. 独立资源、文件和对象存储路径；
4. 查询严格使用本轮生成的业务 ID；
5. 最后才允许按时间范围辅助查询。

## 初始化要求

初始化必须幂等：重复执行不会叠加资源、重复创建业务实体或覆盖其他测试数据。每次写入前保存旧值，写入后回读；影响行数不符合预期时立即停止本轮准备。

## Fixture 复用

同一个 Fixture 可以服务多个 Case，但只允许复用“定义”，不允许无条件复用已经被消费后的运行态数据。对可变资源、余额、库存和次数，必须在每个 Case 前恢复到指定值，或者为每个 Case 分配独立主体。

Fixture 依赖关系至少记录：

```text
fixture_id -> case_ids -> mutable_resources -> reset_strategy
```

准备测试数据时先“租用”测试主体，再执行初始化：

```text
选择 UID/租户 -> 检查是否被其他 run 占用 -> 写入 test_run_id 标识
-> 初始化目标状态 -> 回读验证 -> 冻结 -> 执行 Case
```

如果无法确认账号未被其他测试使用，必须记录并发污染风险；不能通过“最近一条数据”推断当前 Case 的数据归属。

## 并行安全

只有资源集合不相交的 Case 才能并行。以下任一相同都视为冲突：主体、租户、资源窗口、业务实体、任务、对象存储路径、缓存键、幂等键、外部账户或限流配额。冲突 Case 必须串行并在上一个 Case 收口或复位后执行。

## 清理要求

清理不是默认行为。执行前必须明确是否允许清理、清理对象、对异步任务和账本的影响、清理失败如何记录以及是否保留数据用于复盘。

没有安全清理方式时，记录残留数据和影响范围，不执行猜测性的删除 SQL。

## 可复现性

保存请求体、输入文件指纹、测试数据版本、时间、随机种子、代码/部署版本、配置摘要和外部依赖结果。敏感值只保存摘要或脱敏值。
