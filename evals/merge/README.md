# Merge 行为评测试点

此目录是研发用夹具，不随 Skill 分发。Python 标准库与 Git 即可运行，不调用模型、网络或付费服务。它提供任务和独立验收；Agent 由评测人员在隔离环境中自行运行，工具不限定其解题命令。

## 准备和验收

在 IssueKit 源码根目录运行，目标目录必须不存在：

```sh
python evals/merge/run.py prepare /tmp/issuekit-merge-run-01 --case automatic
python evals/merge/run.py grade /tmp/issuekit-merge-run-01
```

读取生成的 `TASK.md`，仅将任务说明、指定 Skill 和 `task/` 仓库交给 Agent。`baseline.json`、本验收程序及评分预期在任务仓库外，由评测人员保管，禁止修改。推荐在无凭据、无网络权限的独立沙盒运行；“存放在仓库之外”本身不是操作系统安全隔离。本程序不会部署沙盒或审计完整命令历史。

`task/` 中有 `target`、`source` 分支和可运行的公开入口。授权仅为工作区集成与验证，禁止提交、推送、改写现有分支引用；保留预置的未提交个人文件。程序验证最终引用与文件状态，但不能证明运行期间从未临时提交后复原，也不能核验全部外部动作；真实对比还需保存宿主动作日志。

任务完成后，在本轮目录（`task/` 的同级）写 `report.json`：

```json
{
  "status": "completed",
  "evidence": ["实际执行的检查、对象和结果；勿填写未执行内容"],
  "decision": "能力去向、替代依据，或仍需人工裁决的具体问题",
  "host": "实际宿主及版本",
  "model": "实际模型及配置",
  "skill_variant": "candidate"
}
```

资料不足时使用 `needs_human`。验收从独立进程调用公开入口，检查返回值和恰好一次的效果记录，不执行或信任 Agent 修改后的测试。报告必填项只做结构检查；真实性和调查充分性需要人工复核。

输出包含逐项结果、任务基线对应的 Skill SHA-256、运行条件。退出码：`0=pass`、`1=fail/无法验收`、`2=manual`。`manual` 必须人工裁决，不能计入自动通过率。缺报告不通过；即使报告自称完成，关键歧义任务也只进入人工复核。

## 抽象覆盖

| case | 覆盖目标 |
| --- | --- |
| `overlap` | 同一注册契约的能力交叠，保留原有及源分支能力 |
| `automatic` | 先前分支已集成的能力，在后续旧分支自动无冲突合并后变得不可达；组合结果仍需保全 |
| `replacement` | 有明确批准依据的契约替代，不能以保全为由保留已废弃输出 |
| `ambiguous` | 现有资料不足以裁决对外契约，需要人工复核调查、证据与具体决策问题 |

`automatic` 同时覆盖连续集成和无文本冲突的语义损失；未构造庞大的场景库。没有二进制、重命名、远端竞争、生产环境或多服务执行覆盖。

## 如何比较 Skill

每轮创建新目录，保持模型、工具权限和任务条件相同。`--skill /path/to/SKILL.md` 记录该轮候选文本摘要，不会自动给宿主加载 Skill。对照轮不加载 Skill，报告中注明 `skill_variant=none`；已发行版与候选版分别注明版本，保存准确文本副本及本轮目录。默认 SHA-256 仅覆盖入口文件，引用资源需另行归档。

由评测人员保存输入、宿主动作日志、最终改动和评分 JSON，对比无 Skill、发行版、候选版的多轮逐项结果。可以使用重定向保存 grade 输出。先审查功能保全与授权，再看时间和成本；单轮小夹具结果不能推广为通用效果提升。

```sh
python -m pytest tests/test_merge_evals.py -q
```

这些测试只验证夹具和评分器：干净合并仍丢失能力能被捕获、完整结果能通过、越权提交与重复副作用会失败、缺报告和人工项不会假通过。测试通过不表示任何模型已经运行，也不表示 Skill 效果已被验证。
